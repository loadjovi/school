# 單日復課與老師登入歷史

## 單日停課與復課

學校管理員從「課表與行事曆 → 課表與停課」操作。原課程列的「停課」會開啟頁內表單，選上課日期並填原因後確認。復課在「停課與復課紀錄」找原堂，按「取消停課／恢復上課」，核對不可改動的日期與原時段、填復課原因後確認。

復課僅將同一課程同一日的取消狀態改為上課，不重匯入課表，不修改其他日期或點名歷史。原停課原因、時間、復課操作人及前後異動保留。日期必須是原課程上課日，只有仍為停課的紀錄能復課。過期畫面或同時修改會回傳 409，要求重新讀取。一般老師、家長與其他學校不能維護此課表。

## 老師完整登入歷史

學校管理員從「操作紀錄 → 老師完整登入歷史」查詢；老師帳號清單也可直接開該老師紀錄。依台灣日期起迄、老師及結果篩選，每頁 100 筆，可逐頁往前查詢，沒有最近 500 筆的截斷。

老師成功進入已授權的老師身分，或已完成 Google 驗證但老師身分被拒絕，會留下紀錄。同一個 Google 登入憑證與學校、結果使用原子交易去重，重新整理不重複計算，重新登入則新增。一般、個課及短期支援老師皆納入。原最近登入時間在新增成功登入時更新。

紀錄從功能啟用後開始累積；過去只保存最近一次的資料不能還原為逐次歷史。Google 驗證前的密碼或驗證失敗無法可靠對應老師，因此不偽造為老師登入失敗。紀錄不保存 Google ID Token、密碼或學生名單。

使用獨立的學校分區保存在既有 SchoolAccessLog 表，讀取 API 僅接受學校管理員的目前學校情境，日期及篩選條件在伺服器檢查。前端不傳送或取得用於去重的內部憑證摘要。

## 驗證

新增測試涵蓋復課後點名恢復、其他日期仍停課、原原因保留、權限與跨校隔離、過期紀錄與 ETag 衝突、重複登入去重、台灣日期邊界、超過 200 筆的分頁、個課老師及已驗證身分拒絕、me 回應不外洩內部登入摘要。

正式與 UAT 兩條部署流程均執行新測試。既有部署必跑的前端回歸與 LAB 隔離檢查亦須通過。完整儲存庫測試另有四個在原 main 即存在的測試問題，已在原版本重現：taipeiDate 與 followupDigest 測試注入缺漏、文件事件模擬缺漏，以及 uniform-event-rules 測試重複匯入。這四項不由本次功能變更引入。
