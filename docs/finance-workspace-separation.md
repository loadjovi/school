# 財務核帳獨立工作區（LINE LAB）

首頁「財務核帳」使用獨立且可保留狀態的工作區。只有本校 admin 且 capabilities.financeVerifier 為 true 的人員可看見、開啟與操作；直接網址也須重新驗證財務資格。既有 DEMO 收費專案維持關閉。

財務工作分為待核帳與補退款、匯款帳戶、團服價格、活動收費與財務通知。沿用原團服、家庭活動、幹部／志工的核帳及補退款 API，不複製款項資料、不另建收費流程。核帳與二次補款足額確認仍由原 API 推進庫存保留、採購需求及發放。付款通知維持 LINE 優先、未受理改寄 Email；自動通知與人工補送保持原去重條件。

團服與活動只保留申請審核、活動資料、報名、採購、庫存與發放；不顯示財務表單、帳戶編輯、通知歷史或催繳按鈕。一般幹部核准前只可讀取帳戶是否已設定的 boolean，不取得完整銀行帳戶。活動資料更新省略財務欄位，後端沿用已存費用與收款設定。

財務專屬 API 在帳戶完整讀取、財務通知讀取／補送及財務寫入前驗證權限；原申請家長依授權與公開條件取得匯款帳戶的行為保留。一般操作紀錄排除財務細節。銀行、通知與申請仍依 schoolId 隔離。

共同底層頁面依 workspace=finance 顯示財務工作區，其他情況顯示團服與活動。進入前就設定視圖 class，避免閃出其他功能。依工作區選擇附加模組並等其載入完成才發出授權事件，避免借還或歸還模組錯過初始化。財務視圖不載入採購／庫存操作附加模組。

財務異動後透過驗證來源、學校及使用者範圍的 iframe 訊息更新操作清單。僅重讀流程與庫存資料，不重載主程式、不覆寫活動草稿。返回工作首頁仍採原有訊息橋接，保留主畫面登入與框架，避免框中框。

驗證涵蓋角色與跨校拒絕、家長授權、直接 API 權限、原核准與補款後採購進度、獨立導覽與返回、模組初始化、通知去重、設定並行編輯與銀行帳戶讀回。未操作真實付款、補退款或對外發送通知。
