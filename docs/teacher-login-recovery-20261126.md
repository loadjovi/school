# 老師登入返回頁恢復

截圖檢查碼 `TCH-HTTP-401` 來自老師 LINE 綁定返回流程的 `/api/me`：該瀏覽器未取得可驗證的 Gmail 身分。單憑截圖不能判定 Google 或 LINE 各自的授權在哪一步失敗，也不能推論老師綁定或名冊已失效。

## 已重現並處理的範圍

原「已完成綁定，使用 LINE 登入」按鈕會清除暫存返回提示，但尚未清除原分頁的 `teacherLineAccount` 網址。Safari 若返回原分頁，該網址仍可能重新啟動舊的 Gmail 綁定返回流程。

現在只有在同一畫面收到並驗證合法 LINE 授權網址後，才先更新原分頁網址、清除舊的老師／家長 OAuth 返回參數與提示，再開啟純 LINE 登入。失敗或過期的非同步結果仍不得改動目前身分、網址或提示。

## 重新開始登入

老師返回頁出現錯誤時提供 `/login-reset.html?schoolId=...`。這個獨立入口：

- 僅清除目前分頁已知的登入與返回提示，保留練習及申請草稿。
- 等待同站 Google 與 LINE 登出均成功，才返回乾淨的共同登入入口。
- 網路、瀏覽器儲存或導航失敗時停留在原頁，提供重試，不假稱成功。
- 只保留一個格式正確的學校提示，不接受外部返回網址、角色或憑證參數。
- 不解除 LINE／Gmail 綁定、不異動學生關係、不自動授權登入，也不修改名冊權限。

既有 Google 憑證優先規則、OAuth state／CSRF 與同校老師身分驗證保持原樣。失效的明確 Google 憑證不會改借其他 Cookie 或 LINE 身分。

- 變更 JavaScript 語法及 `git diff --check` 通過。
- 正式公開設定與 LINE 學校入口正常回應；未登入 `/api/me` 返回 401 是正常保護。

測試使用隔離瀏覽器狀態與模擬網路，未查看或修改老師私人登入憑證、帳號綁定、名冊或學生資料。老師手機上的實際結果，仍需從新恢復入口重新登入後核對，不能以程式回歸宣稱其私人登入已成功。
