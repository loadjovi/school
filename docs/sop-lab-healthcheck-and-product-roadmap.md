# 聖心弦樂成長平台｜第二階段功能深化與效能治理計畫

> 狀態：規劃，不代表功能已上線。此文件僅定義 SOP LAB 驗證與正式區上線門檻。

## 先做基準，不先改正式資料

本階段先在 **獨立 Functional UAT SOP LAB** 測量四條路徑：
1. 家長：已完成 Google 登入後的 `/api/me → /api/students → /api/summary + /api/practice`（不含外部 OAuth 時間）。
2. 個課老師：已登入後的 `/api/students + /api/private-lesson`。
3. 校方查詢：`/api/school-followup?date=YYYY-MM-DD`。
4. 管理員首頁：`/api/student-registration`、`/api/student-master`、`/api/uniform-events/requests`、`/api/daily-followup`，按角色需求再查核帳 API。

測量以同一裝置、網路與角色執行至少 20 筆有效樣本後，再比較 p50/p95、失敗率與回傳量；工具初次 3 次測量只作功能與基準檢查，**不視為完整 p95 或 Google 登入耗時**。不同角色分開統計，禁用正式使用者的真實資料匯出；報告只能輸出情境、API 分類、HTTP 狀態、時間及傳輸量，不包含名單／帳號／Token。需另外以真實瀏覽器 DevTools 取得 LCP/INP、頁面繪製與登入時間。

## 方向 A：音樂學習歷程（優先產品功能）

### 第一個版本：老師本週練習建議 → 家長自主練習

- 個課老師在「完成上課」流程中可填寫 **本週練習重點**（建議最多 3 項），例如「降 E 大調音階」「第 18 小節換把」「慢速 60 BPM 完成兩次」。
- 不能只依賴自由文字的「上課內容」自動抽取規則；每一項練習重點都是可追溯、可編輯、可帶入家長端的獨立欄位。
- 家長自主練習頁顯示「老師本週建議練習」，附指定老師、個課日期、項目與（可選）達成條件；**不自動等同老師評分，也不要求家長每日填寫更多欄位**。
- 家長可選擇練習項目，日報連結該項目；下次個課老師能看到過去一週練習完成情形，並提供「已改善／持續練習／調整目標」回饋。
- 沒有個課紀錄、或當週老師未指定練習目標時，只顯示一般自主練習，避免空白錯誤或強行給分。
- 舊版個課、練習日報、評量與成績保持不變；資料分校分學生隔離，家長只能看綁定學生，老師只能看有授權的個課學生。

**LAB 驗收：** 個課老師儲存 → 家長看到建議 → 家長練習打卡並選取項目 → 老師看到已完成／待加強 → 異動有時間、帳號及版本；重新載入與手機切換不遺失草稿。

### 後續擴充

- 演奏曲目與小節範圍、分部老師回饋、期末學習評量串接。
- 依時間序列呈現每位學生的「學習軌跡」，預設只顯示相關人員有權限的資料。

## 方向 B：通知中心與追蹤規則

建立統一的通知事件紀錄，但不立即取代目前已運作的 Email。
- 事件與狀態分離：`需通知 → 待發送 → 已寄送 / 失敗 → 使用者已操作`。
- 「已寄送」只能表示寄送供應商結果，**不得推論收件人已讀或已處理**；收到老師／家長的實際操作後才能標記流程已處理。
- 跨個課預約、缺席、家長確認、團服與費用的通知鍵具唯一性，同一事件不重複寄；提醒頻率、到期日與重送次數須有上限。
- 因個別角色不同，通知應分流到「老師待辦、家長待辦、學校／幹部待辦」，不可把已送出待家長確認誤列老師未完成。
- Email 發送失敗不能使已成功寫入的點名／練習／完課變成失敗；人工重送需權限、紀錄及避免重複寄送。
- LAB 全程使用虛構帳號與隔離環境，不得寄送真實學校 Email。

**LAB 驗收：** 去重、取消／撤回、權限隔離、逾期提醒、寄送失敗與重新寄送、操作後的狀態同步、歷史查詢。

## 方向 C：正式營運與稽核

- 完整列出關鍵異動的前後內容：何人、何時、何校、哪位學生／哪筆業務、異動來源、修改前／後差異；不要把登入或寄信誤認成業務完成。
- 學期成績結算鎖定與重開流程：結算後不可默默重算歷史成績，修正需有權限、原因與版本；產生可查的最終 CSV 快照。
- 不把 Token／密碼寫進 log 或匯出檔；日誌與匯出記錄採最小必要權限與保留期限。
- 定期以 LAB 演練完整備份、校驗、還原與資料抽查，確認備份涵蓋必要的課程、個課、出勤、成績、團服、財務與權限資料。
- 每次部署檢查正式／LAB 版本、專用憑證、Azure Storage 帳戶、Email 限制與資料隔離。**絕不為求同步而將正式學生資料直接複製到 LAB。**

**LAB 驗收：** 角色權限矩陣、歷史異動查詢、成績鎖定與授權重開、可稽核的還原演練、正式/LAB 隔離測試及回歸測試全部通過。

## 推進順序與停損

1. **P0** 完成四條流程唯讀效能基準，修正速度最慢或失敗率最高的實際瓶頸；先蒐集結果，不預判瓶頸。
2. **P1** 在 LAB 加入「個課本週練習建議」最小可用流程，由老師與家長驗收，不變更目前自主練習評分計算。
3. **P1** 統一通知事件與待辦狀態，先完成去重、可查、逾期提醒，再考慮整合 Email 發送。
4. **P2** 強化稽核／成績鎖定／還原演練；涉及正式資料遷移時需先完成備份、影響分析與逐項同意。
5. 每階段均須經 LAB 實測、回歸測試、行動裝置驗收，才可考慮正式上線。功能開發不應繞過現有隔離與審核流程。
