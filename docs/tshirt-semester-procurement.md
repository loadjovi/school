# 團 T 本學期採購總表

入口：學校後台 → 團服與活動 → 團 T → 採購總表。

整合在團學生首次公費、學生加購、幹部首次公費、幹部自費加購、志工自費加購。學生補登原有團 T 尺寸不構成加購；志工借用及送洗不自動形成新購需求。首次公費每人一件，已交付但尚未家長確認者不再採購。退團學生不列入目前需求。

本學期預設依台北日期判定：上學期 8/1 至翌年 2/1 前，下學期 2/1 至 8/1 前。加購以申請建立日期歸期，較早學期未結案需求另外併入並標示。首次需求以目前在團名冊為基準，查閱舊學期不代表當時名冊快照。

各尺寸規劃：尚待供應 − 正式可用庫存 − 已採購備貨待到貨，最低為零。庫存可用數為 onHand − reserved − unavailable。缺少庫存資料不等於零。待填尺寸列入需求總量與明細，但不能分配到採購尺碼。另加備貨是本次頁面的試算值，匯出可留存，不會自動形成訂單；重新開頁清除。

完整 CSV 包含總計、各尺寸、需求名單、未完成事項及志工借用；廠商版只保留總計與尺寸，不提供姓名或學生 ID。兩版都採 UTF-8 BOM 並防範 CSV 公式注入。缺少任一必要來源時，清空統計並停用匯出，不以舊數據或零件數誤導採購。

## 幹部／志工需求

在採購總表或幹部／志工入口登記。以已綁定家長帳號識別，包含本人姓名、關聯學生、類別、學期、尺寸、件數、備註。幹部首次公費的終身資格以家長帳號去重，不因有兩位孩子而增加。既有領用／借用紀錄仍有效；新增需求不會直接發放、入庫或扣庫存。

自費款項依後端現價計算，初始待財務核帳。只有具有 financeVerifier 權限者能確認入帳，必須提供實際日期、與應繳一致的金額、末五碼及核帳說明。未核帳不能標記已採購。進度為已確認 → 已採購 → 已到貨 → 已處理完成；實際入庫與發放依原流程另行登記。取消僅限未下單需求，且須說明。所有異動保留稽核及 etag 併發檢查。

沿用已部署的 `/api/uniform-events/parent-loans` 路由，以 `?view=procurement` 取得新增需求，另存 `TenantTshirtStaffDemand`，依認證學校隔離；一般領用／借還回應保持原狀。新增 action 為 ADD_DEMAND、VERIFY_DEMAND_PAYMENT、UPDATE_DEMAND_STATUS。只有學校管理員可使用，非財務人員不能取得銀行核帳細節。

## 統一採購、到貨與家長需求（2026-11-22）

團 T 以 `TenantTshirtPurchaseOrders` 的整張採購單為主。採購總表建立訂單時，納入可由該單尺碼供應的已核帳家長及幹部／志工需求，保留來源 ID；同一需求的關聯與採購單以同校 Table transaction 寫入，不可重複納入另一張有效採購單。未納入的首次公費與備貨在到貨後供原領用流程使用。

整單驗收使用實際到貨日期及驗收備註，一次寫入各尺寸正式庫存、家長件數保留、每筆家長入庫帳及整單到貨帳。重試不重複入庫。家長轉為可以領取並依既有 LINE 優先、Email 備援通知。實際發放才扣在庫及解除該家長的保留件數。現有庫存足夠且未納入採購單的已核帳申請，可直接保留庫存並開放領取。

既有待到貨採購單可展開「整合待採購／舊申請」，人工核對後選入同一批的舊個別採購或已到貨申請。已到貨申請不預先勾選；尺碼與件數須符合本單且原入庫來源明確。整單驗收僅增加本單尚未入庫的淨件數，不會重複增加既有到貨。已領取申請不退回待領取。不屬於同批的到貨不可僅因尺碼相同而自動合併。

採購狀態為 ORDERED → RECEIVING → RECEIVED；後續需求或通知同步失敗會明列待同步，可在同張採購單重試。未驗收且未整合舊到貨的採購單可取消，需求回到原進度。舊個別新貨驗收保留相容性供既有紀錄修復，前台新採購與到貨一律從採購總表處理。


## 處理中需求與已完成發放

採購總表的六項統計、篩選名單、尺寸合計與採購 CSV 僅計算處理中需求。已採購、已到貨或可領取仍屬處理中；家長加購確認實際發放（FULFILLED）後，另列於預設收合的「已完成發放（歷史紀錄）」，保留原申請與發放時間。同一學生先前完成的 S 號加購與後續新的 XS 號申請以不同 request ID 分開，不會因學生相同而合併或覆蓋。

首次公費已實際交付及幹部／志工已完成領用亦不再計入目前採購；學校已交付但家長尚未確認者，歷史紀錄標明待家長確認。完成資料為唯讀分類，原始紀錄、庫存與採購單不因切換顯示而異動。

## 家長加購優先使用現有庫存

家長加購仍須先完成審核、匯款及財務核帳（含補款後二次核帳）。同尺寸可用的新團 T 足夠整筆申請時，自動保留申請件數並開放領取，後台直接顯示「確認實際發放」；不建立廠商採購數量或增加在庫數。庫存不足、不曾盤點或尺寸未確認者維持採購需求，由採購總表處理。已拆封團 T、志工借用、其他申請保留量與不可用數量均不得挪用。

現有庫存分配與正式採購單使用相同需求 claim，避免同筆申請同時採購與領用。保留量與申請來源帳一併提交，實際發放才扣在庫及此筆保留量。分配成功而申請更新失敗，可由重新整理的明確 POST 同步，重試不重複保留；已在正式採購單內的申請仍由整單到貨流程處理。後台供應來源標示「現有庫存」，不誤記為向廠商採購。
