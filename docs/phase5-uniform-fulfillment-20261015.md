# 第五階段｜團服發放、庫存與活動結案

## 第一批：實際發放（PR #22 預覽環境）
- 學校後台於申請進度「可以領取」時確認實際領取人和發放備註。
- 自費項目必須先由財務確認入帳；公費配發無須付款。租借及取得方式待核對的單據不在此流程發放。
- 後端檢查尺寸、件數和可用庫存，將庫存扣減與每筆申請唯一的發放紀錄寫入同一筆 Azure Table 交易，避免重複扣庫存。
- 申請進度更新為「已領取」，家長可查看領取日期、領取人與件數；成長紀錄僅將正式完成的領用算作已取得。
- 發放紀錄按學校隔離，包含申請 ID、學生 ID、尺寸、件數、時間、操作人、領取人及備註。若庫存交易成功但跨表申請更新失敗，管理員重新操作可完成狀態同步而不重複扣庫存。

## 後續待完成
1. A 團公費服借還、送洗、損壞與資產編號；尺寸交換、退還及庫存回補。
2. 完整學生歷史領用資料核對與匯入，建立首次免費資格的可靠資料來源。
3. 採購、到貨與保留量的正式流轉及異常處理。
4. 活動名額、取消更正、退款、結案收支及最終名單。
5. 真實 Azure Table Storage 的競爭寫入、重試、付款和跨校權限端到端測試。

第四階段尚未完成的帳戶快照、異常核帳及財務權限實測仍為正式啟用前門檻；此批僅供預覽驗收，不合併 main。
